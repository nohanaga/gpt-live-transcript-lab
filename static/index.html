        表示モード・時間軸の説明
        
公式仕様・実装を確認

        
横軸は時間、レーンは処理種別です。短い処理も名前を読めるラベル幅を確保し、重なるラベルは段を分けます。上端の線が実測の実行・待機区間、短い縦マーカーがイベント時刻です。箱全体の幅は所要時間ではありません。pending / buffered / current は状態の保持期間であり、CPU 処理時間ではありません。

        
等倍の時間軸は 1 ms = 1 px を維持します。「リセットからの経過時間」や目盛りをドラッグすると縦横にスクロールできます。横方向へ移動すると「最新時刻を追従」を自動で OFF にします。再び追従するには検索・表示オプションで ON にしてください。

        
ドラッグを離すと、直前の速度に応じて滑らかに減速します。押し直す・ホイール操作・キー操作で慣性スクロールを停止できます。離す前に手を止めた場合や、端に達した場合は滑り続けません。端末で動きを減らす設定が有効な場合は、慣性を付けません。

        
全体表示では波形を左右にドラッグして時間範囲を選択できます。離すと、その区間に重なる処理・本文・波形を拡大表示します。選択中は最新時刻へ追従せず、記録は継続します。「全体表示に戻す」で解除できます。ドラッグ中の Escape は選択を取り消します。

        
処理と波形は記録開始からの全履歴を保持し、時間経過や件数による自動削除は行いません。画面外のバーは縦横スクロール時に描画します。再読み込み・リセット前に必要な履歴を JSON 保存してください。

        
本文は RAW 差分 / Grouper 全文 / Ledger 全文を区別します。上端のマーカーが記録時刻・時間区間です。範囲選択中は端のラベルを内側へ寄せるため、カード左端と記録時刻が異なる場合があります。カード幅は読みやすさのためのもので、発話時間ではありません。選択すると省略なしの本文（Ledger は消費済み / 未消費も）を表示します。Ledger のローカル時刻は snapshot の受信時刻です。

        

        

        
波形はマイク入力と AI の受信音声をローカル時計に推定配置します。薄色はピーク、濃色は RMS（音量の目安）。音声自体は保存しません。受信波形はスピーカーでの再生完了や発話判定を示しません。

        
Python の所要時間はサーバーで実測し、ブラウザーの往復区間内に推定配置します（時計は未同期）。HTTP の認証・セッション作成は Server-Timing に基づきます。API が公開しない推論過程・VAD・ツール内部処理は観測不可です。公開された response.event は GPT-Live モードで確認できます。音声トラックの有効期間や HTML audio の再生状態は、実際の発話区間・聴取完了を保証しません。表示停止中も記録は継続します。

      機能仕様と公式ドキュメント
      

        
WebRTC / セッション
音声は media track、JSON イベントは data channel で転送されます。認証と SDP のセッション作成はサーバー経由です。Azure GPT-Live WebRTC

        
TranscriptGrouper / SDK helper
公開 transcript の話者・ソース時刻・相づち判定から表示用セグメントを生成します。曖昧な話者切り替えは最大 50 ms 待機。segment.updated は全文の置換で、inactivity / segment.closed は音声終了や VAD の通知ではありません。固定コミットの公式 SDK 実装

        
TranscriptLedger / Cookbook sample
同じ話者の近接する fragment を記録し、consume_srt() で未消費テキストを取得してローカル消費カーソルを進めます。Live API の受信確認ではありません。公式 Cookbook 実装

        
Client delegation / このアプリの実装
Ledger の SRT を選択した判断モデルへ渡します。Function Calling 方式では、Azure OpenAI Responses API でモデルが生成した関数呼び出しの引数を検証し、アプリが search_weather を実行します。Jev 方式では、事前定義候補と信頼度の検証後にアプリが実行します。Jev 方式は実結果の日本語要約を使用し、Function Calling 方式は function_call_output をモデルへ戻して回答を作ります。結果は session.commentary.append で返します。関数の成功・失敗と送信・ACK は別状態です。

        
時刻・送信・ACK
start_ms / end_ms とローカル受信時刻は別の時間軸です。prepared / sent / acknowledged / send_failed / rejected を区別します。対応 ID のない ACK を推測で関連付けません。ACK は音声再生完了・操作成功を保証しません。セッションと transcript の仕様
